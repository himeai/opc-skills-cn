# 中国合规边界详解

本文件用于解释 `opc-skills-cn` 的合规约束，帮助 contributor 在设计 skill 时提前识别高风险边界。

## 1. 总原则

本仓库仅接受：

- 基于官方或开放 API 的能力封装
- 明确、可解释、可审计的自动化脚本
- 不绕过登录、不破解协议、不模拟人工的安全实现

本仓库拒绝：

- 爬虫绕过登录
- 协议逆向
- 批量私信、批量加好友、骚扰式触达
- 刷量、虚假评论、伪造互动

## 2. PIPL（个人信息保护法）

如果 skill 涉及个人信息，应遵守以下最小原则：

- 最小必要：只处理完成任务所需的数据
- 明示用途：在 `SKILL.md` 中说明数据用途与边界
- 不落盘：用户输入不得写到 skill 目录外
- 不二次使用：不得将数据用于训练、画像、营销或其他未声明目的

常见敏感数据包括：

- 姓名、手机号、邮箱、身份证号
- 家庭住址、公司账号、支付信息
- 户籍、医疗、税务、招聘简历等高敏感字段

## 3. 数据出境

若 skill 未来接入海外 API，需要额外审查：

- 数据是否包含中国境内个人信息
- 是否会把企业经营数据传出境
- 是否需要在 README 或 SKILL.md 明确风险提示

在没有明确合法基础前，不应默认把中国用户数据发送到海外第三方服务。

## 4. 平台协议

对接微信、抖音、小红书、飞书、企微、支付宝等平台时，必须满足：

- 只调用官方、开放、授权可用的接口
- 不规避频率限制、权限校验、登录流程
- 不伪装成浏览器或手机进行未授权抓取

若平台没有公开 API，默认视为不可自动化，不得以抓包或协议逆向替代。

## 5. 高风险业务域

以下领域可以做“辅助信息”与“流程建议”，但必须谨慎：

### 税务与开票
- 必须写明“不构成税务建议”
- 不应在没有充分校验下自动提交申报

### 法律文书
- 必须写明“不构成法律意见”
- 模板生成不等于律师审查

### 医疗与健康
- 不得生成诊断结论
- 只能提供信息整理、预约辅助、公开资料查询等低风险能力

### 招聘与简历
- 需避免非法采集和滥用候选人数据
- 禁止爬取简历库和绕过平台授权下载简历

## 6. Contributor 自检清单

在提交 PR 前，请自问：

1. 这个 skill 是否只依赖官方或开放 API？
2. 是否有任何爬虫、逆向、刷量、群发行为？
3. 是否处理了个人信息？若有，是否说明了边界？
4. 是否把敏感信息写入文件、日志或仓库？
5. 是否需要额外风险提示？
